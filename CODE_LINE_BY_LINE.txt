CAT AND DOG PROJECT
LINE-BY-LINE CODE EXPLANATION

This document is a companion to PROJECT_GUIDE.txt. It follows the current
source files in execution order and explains the code using the line numbers
shown by:

    nl -ba config.py
    nl -ba src/split.py
    nl -ba src/dataset.py
    nl -ba src/model.py
    nl -ba src/utils.py
    nl -ba src/train.py
    nl -ba experiments/run_search.py
    nl -ba src/evaluate.py
    nl -ba src/visualize.py
    nl -ba tests/test_catdog.py

The line ranges below are explanatory landmarks, not a generated API
reference. They can shift when source files are edited; the code behavior and
symbol names are the authoritative reference.

Blank lines are included for readability and do not execute. Comments and
docstrings explain intent but do not change the model's calculations.


1. config.py
============

Line 1
    Module docstring. It identifies this file as the central configuration
    module.

Line 2
    Imports Path from pathlib so filesystem paths can be constructed in a
    platform-independent way.

Line 4
    ROOT is the absolute directory containing config.py. All project paths
    are derived from ROOT rather than hard-coded separately in each script.

Line 5
    DATA_DIR points to data/catdog_data, which must contain cats and dogs
    subdirectories.

Line 6
    PETS_DIR points to the optional personal images used for qualitative
    predictions.

Lines 7-9
    OUT_DIR is the general output directory. CKPT_DIR stores model
    checkpoints, HIST_DIR stores CSV training histories, and FIG_DIR stores
    generated figures.

Line 10
    SPLIT_FILE is the JSON file containing train, validation, and test image
    lists.

Line 11
    STATS_FILE caches the RGB mean and standard deviation calculated from the
    training split.

Line 12
    RESULTS_FILE is the configured location for the experiment CSV. The
    completed experiment table currently exists at experiments/results.csv;
    the search script uses the configured path when it is run.

Line 14
    CLASS_FOLDERS maps folder names to integer labels. Cats are label 0 and
    dogs are label 1.

Line 15
    CLASSES maps those integer labels back to display names.

Line 17
    SEED controls the deterministic data split.

Line 18
    IMG_SIZE sets the height and width used by the transforms: 128 by 128.

Line 19
    NUM_WORKERS controls how many worker processes load images. Setting it to
    zero is a useful fallback on systems with DataLoader worker problems.

Line 21
    SPLIT stores the requested proportions: 70 percent training, 15 percent
    validation, and 15 percent test.

Lines 24-38
    DEFAULTS stores the default model and training hyperparameters. These
    values are used whenever a run does not provide an override.

Line 25
    base is the number of output channels in the first convolutional block.
    Later blocks double this number.

Line 26
    n_blocks controls the number of convolutional blocks.

Line 27
    dropout is the probability used by the classifier's Dropout layer.

Line 28
    batchnorm controls whether BatchNorm2d is inserted after convolutions.

Line 29
    augment controls whether random training augmentation is enabled.

Line 30
    optimizer selects Adam, AdamW, or SGD in train.py.

Line 31
    lr is the optimizer learning rate.

Line 32
    weight_decay adds optimizer-level L2-style regularization.

Line 33
    batch_size is the number of training images processed before each update.

Line 34
    epochs is the maximum number of passes over the training data.

Line 35
    patience is the number of non-improving validation epochs allowed before
    early stopping.

Line 36
    scheduler controls whether ReduceLROnPlateau is used.

Line 37
    seed controls model initialization and other training randomness.

Line 40
    BASELINE defines the deliberately unregularized comparison: no
    augmentation, no dropout, and no weight decay.

Lines 42-43
    The loop creates all output directories when config.py is imported. This
    means later scripts can save checkpoints and figures without first
    creating the directories manually.

4. src/model.py
================

Lines 1-4
    Imports PyTorch, neural-network layers, and the trainable-parameter
    counter.

Lines 7-30: SmallCNN
    Defines the custom convolutional neural network.

Line 8
    Documents the repeated block pattern and classifier head.

Lines 10-11
    Initializes the parent nn.Module and an empty layer list. in_ch starts at
    3 because input images have RGB channels.

Lines 12-18
    For each block, calculates output channels as base times 2 to the block
    index. Adds a 3x3 convolution with padding 1, optional BatchNorm2d,
    ReLU, and 2x2 max pooling. The next block receives the current output
    channel count.

Line 19
    Wraps the list of feature layers in nn.Sequential so they execute in
    order.

Line 20
    Adds adaptive global average pooling. Regardless of the input spatial
    size at this point, it produces one value per channel.

Line 21
    Adds configurable dropout before classification.

Line 22
    Adds a linear layer producing one logit for each class.

Lines 24-26: forward()
    Sends the input through features, global pooling, flattening, dropout, and
    the final linear layer. The output is raw logits; CrossEntropyLoss
    performs the appropriate log-softmax internally.

Lines 29-30: build_model()
    Reconstructs SmallCNN from a configuration dictionary. This ensures a
    checkpoint can be loaded with the same architecture that created it.

Lines 33-40: load_model()
    Loads a checkpoint onto the selected device, rebuilds the model from the
    stored configuration, restores learned parameters, switches to
    evaluation mode, and returns the model and configuration.

Lines 43-49
    The direct-execution check builds the default model, runs a random batch
    through it, prints the architecture, verifies the output shape is
    batch-by-two, and reports trainable parameter count.

7. experiments/run_search.py
=============================

Lines 1-8
    Module documentation describes the four-stage, resumable search.

Lines 10-11
    Imports argument parsing, CSV support, configuration, and the train()
    function.

Lines 13-22: BEST
    Stores the validation-only configuration used by the original staged
    search. It uses base 64, four blocks, AdamW, learning rate 1e-3, weight
    decay 1e-4, batch size 32, no scheduler, no augmentation, and no
    dropout. The later fair retest was run directly through train() and did
    not replace this historical search definition.

Lines 24-57: STAGES
    Defines experiment names and overrides.

Lines 25-33: Stage 1
    Compares the baseline, augmentation, two dropout strengths, two weight
    decay values, and BatchNorm disabled. This tests regularization choices.

Lines 34-42: Stage 2
    Compares three, four, and five blocks and base widths 8, 32, and 64. This
    tests depth and width while carrying forward BEST.

Lines 43-51: Stage 3
    Compares learning rates, batch sizes, SGD, and a validation-loss
    scheduler. This tests optimization behavior.

Lines 52-57: Stage 4
    Trains the selected configuration with seeds 42, 1, and 2. These runs
    measure sensitivity to initialization, batch order, and augmentation
    randomness. The seed is passed to the DataLoader generator.

Lines 59-60
    Defines the CSV column order: metrics first, then all default
    hyperparameters.

Lines 63-70: done_names()
    If the results file does not exist, returns an empty set. Otherwise,
    reads the CSV and returns all completed run names. This makes interrupted
    searches resumable.

Lines 73-79: append()
    Opens the result file in append mode, writes a header for a new file, and
    writes one result row.

Lines 82-103
    Parses the required stage number, obtains the stage definition, and loops
    over experiments.

Lines 88-91
    Builds the run name and skips it if already recorded. Otherwise merges
    DEFAULTS, BEST, and the experiment override.

Lines 92-98
    Trains the configuration and creates a compact row with best validation
    metrics and the train-validation accuracy gap.

Lines 99-103
    Adds all hyperparameters, appends the result, and prints a concise
    progress line.

Experiment interpretation
-------------------------

The completed results show that:

    Stage 1:
        There was no clear effect from weight decay alone: wd1e-4 was only
        about one percentage point above the no-decay baseline. wd1e-3 had
        the lowest validation loss.
        Dropout 0.5 performed poorly and BatchNorm removal reduced accuracy.

    Stage 2:
        Width 64 achieved the strongest validation result, approximately
        79.4 percent accuracy and 0.486 validation loss. The wider model has
        many more parameters, so the parameter/accuracy chart is important.

    Stage 3:
        AdamW with learning rate 1e-3 and batch size 32 remained strongest.
        Batch size 64, SGD, and the tested scheduler were weaker in the
        original short-budget comparison.

    Stage 4:
        Validation accuracy varied across seeds: approximately 79.4, 77.5,
        and 75.0 percent. This is why reporting only one run would hide
        training variability.

    Stage 5:
        Reproduces the fair long-budget comparison: three augmented seeds,
        three non-augmented seeds, and augmented width-8 and width-16 runs.
        All use the same 100-epoch maximum, patience 20, and scheduler.

    Fair retest:
        The original augmented run had a shorter training budget, so
        augmentation and no augmentation were retrained for up to 100 epochs
        with patience 20 and ReduceLROnPlateau. The augmented configuration
        With seed-dependent DataLoader order, the augmented runs achieved
        78.3, 83.9, and 79.2 percent validation accuracy. This corrected
        comparison is the basis for the validation-loss selection rule.

11. FILE-TO-FILE EXECUTION FLOW
================================

1. config.py is imported by the other modules and creates output folders.
2. split.py imports config, validates images, and writes split.json.
3. dataset.py reads split.json, calculates stats.json, and creates loaders.
4. model.py builds the CNN from a configuration dictionary.
5. train.py combines the loaders and model, computes loss, backpropagates,
   updates weights, validates, and writes checkpoints/history files.
6. run_search.py calls train.py repeatedly with controlled overrides and
   writes experiment results.
7. evaluate.py loads final.pth, predicts the held-out test set, and writes
   metrics, a confusion figure, and misclassified_final.json.
8. visualize.py loads the final checkpoint and reuses loaders and predictions
   to create interpretation and comparison figures.
9. tests/test_catdog.py imports split, dataset, and model components to check
   the core invariants before submission.


12. HOW THE EXPERIMENT RESULTS ARE USED
=========================================

The search uses validation loss and validation accuracy, not test accuracy,
to choose BEST. The test set was evaluated for the original checkpoint and
the three fair augmented checkpoints; none of those test results was used
to choose the promoted configuration.

The original staged search selected:

    base=64, n_blocks=4, batchnorm=True
    augment=False, dropout=0.0
    optimizer=AdamW, learning rate=0.001
    weight decay=0.0001, batch size=32, scheduler=False

Its seed-42 validation result was 79.44 percent accuracy with validation loss
0.4860, and its held-out test accuracy was 78.33 percent. The original
checkpoint is preserved as outputs/checkpoints/original_final.pth.

The fair retest used the same architecture but a matched longer budget:

    augment=True, scheduler=True, epochs=100, patience=20

The promoted candidate checkpoints are fair_aug, fair_aug_s1, and
fair_aug_s2. The predeclared selection rule chooses fair_aug_s1 because it
has the lowest validation loss; it is copied to final.pth for submission.
Their
validation results were:

    final     seed 42: 78.33 percent, validation loss 0.5008
    final_s1  seed 1:  83.89 percent, validation loss 0.4342
    final_s2  seed 2:  79.17 percent, validation loss 0.4784

The selected fair_aug_s1 test evaluation was:

    test accuracy: 81.94 percent
    test images: 360
    misclassified images: 67

Confusion matrix, with true classes as rows and predictions as columns:

    cat true: 156 cat predictions, 24 dog predictions
    dog true:  41 cat predictions, 139 dog predictions

The fair retest is reported separately because the original augmented run
received a shorter training budget. The promoted model is selected using
validation results. The three corrected fair augmented test accuracies were
81.67, 81.94, and 81.39 percent (mean 81.67 percent, sample standard
deviation 0.28 percentage points). The original test result was 78.33
percent.

The fair augmentation result is still suggestive rather than definitive, but
it now uses three seeds per setting. The no-augmentation runs averaged about
78.2 percent validation accuracy (76.9, 77.5, and 80.3 percent), versus
about 80.5 percent for the augmented runs. The test set was evaluated
(78.3 percent for the original checkpoint and the three fair augmented
results above), but promotion was based on validation results. The
approximate 95 percent interval for the selected test accuracy is 77-85
percent.

The fair model-size follow-up tested base widths 8 and 16. They reached
77.8 percent with 24,778 parameters and 79.4 percent with 97,938 parameters,
respectively. The 64-base model remains the accuracy choice, while the
smaller runs provide evidence for the parameter/accuracy trade-off.


13. IMPORTANT INTERPRETATION NOTES
===================================

Training accuracy and validation accuracy are not measured under identical
conditions when augmentation or dropout is enabled. Training mode can contain
random image transformations and active dropout, while evaluation mode uses
clean images and disables dropout. A train-validation gap must therefore be
interpreted with the model mode and data transformation in mind.

The original staged search selected augmentation=False and dropout=0.0, but
that comparison was limited by its shorter training budget. The fair retest
gave augmented and non-augmented models the same longer budget and found
that augmentation improved validation accuracy by about four points. For
seed 42, the curves also show that augmentation prevented the clear
memorization pattern seen without augmentation; the best-epoch gap bars do
not prove a general gap reduction across seeds. The promoted current final model therefore uses
augmentation=True and dropout=0.0. The original no-augmentation checkpoints
remain available for comparison.

The selected fair_aug_s1 checkpoint is copied to final.pth. The previous
promoted seed-42 checkpoint is retained as
outputs/checkpoints/previous_promoted_final_fair_aug.pth.

The overfit sanity check reached 100 percent training accuracy by epoch 16
on the 32-image subset. This confirms memorization capacity and basic
training-loop correctness, not generalization.

The available dataset contains 2,400 images rather than the 2,600 mentioned
in the assignment handout. This should be reported and the original zip
should be checked if possible.

The my_pets predictions are not part of the test metric. They are a
qualitative demonstration on images outside the labeled project dataset.
